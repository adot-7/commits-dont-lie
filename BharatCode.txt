Commits Don't Lie — BharatCode Build League, Round 1

What it is
  A harness that drafts build-in-public posts from your git commits and refuses
  to ship any sentence the diff cannot back up. Every claim gets a file:line
  receipt or gets blocked. After a post is published, every later push re-checks
  it and flags it Stale if the code it cited is removed.

Direction
  Coding & developer tools (CLI + web service).

How it uses BharatCode
  All model calls go to the BharatCode model API by default.
  - Base URL:  https://bharatcode.ai/api/model/v1
  - Endpoint:  POST /chat/completions with one forced function tool per call
  - Model:     qwen-3.8-27b (override with BHARATCODE_MODEL)
  - Key:       BHARATCODE_API_KEY (server-side only, never committed)
  - Code:      cdl/bharatcode_client.py (client), cdl/llm.py (drafting and
               entity extraction)
  The model drafts sentences and extracts the files, functions and integrations
  each sentence names. It never decides whether a claim is true. A
  deterministic Python function, cdl/grounding/check.py::claim_vs_diff, makes
  that call by matching the extracted names against the diff.

Try it
  pip install git+https://github.com/adot-7/commits-dont-lie
  export BHARATCODE_API_KEY=bc_live_...
  cd any-git-repo
  cdl check -n 3 "Your post about the last three commits."
